# 実装ルール
**人間**が最短時間でコードを理解できるように実装してください。

## 推奨事項

 - 公式 Action ないしは有名な Action があれば使用すること (org の許可リストに追加する)
   - 理由: 車輪の再発明防止 / コードの可読性向上
   - 例外: 有名ではないサードパーティの Action は利用しないこと
 - PR へのアノテーションコメントはしない
   - 理由: アノテーションを付与する実装は長くなる傾向があり、レビュー負荷が高い。また、AI が開発をするので人間のためのアノテーションは不要である。
   - 例外: コマンドのオプションないしは公式 Action の引数で簡単にアノテーションできるのであれば追加して良い
 - 公式推奨・業界標準・ベストプラクティスにすること (破壊的変更は許容)

## 禁止事項

 - ワークフロー内に直接書く 10 行以上の `run:`
   - 理由: レビュー負荷が高くなり、マージまでの時間がかかるため
   - 対処方法:
     1. Action の利用を検討する。
     2. 「そもそもこの機能/実装は必要か？」「そもそもこの仕様が業界標準・ベストプラクティスなのか？」と振り返る。必要に応じてレビュアーに提案する。
     3. composite action として切り出す（`theindiehacker/devops/<path>@<ref>` で参照する）。
